# API Reference



This document provides a comprehensive reference for the TrackOpenSource API endpoints. The system exposes three tiers of access: **Public endpoints**, **Protected endpoints** (requiring an active user session via Clerk), and **V1 programmatic endpoints** (requiring an API key).

---

## Authentication Schemes

### 1. Clerk JWT (Browser Sessions)
Used by the Next.js frontend to interact with the backend on behalf of a user.
*   **Header:** `Authorization: Bearer <token>`
*   **Validation:** RSA-256 signature verification against Clerk's public JWKS, validating `iss` (Issuer) and `azp` (Authorized Party).

### 2. API Keys (Programmatic Access)
Used by developers for server-to-server or script integration.
*   **Header:** `x-api-key: osr_<key>`
*   **Validation:** SHA-256 cryptographic hash lookup in the `api_keys` table.
*   **Rate Limits:** 100 requests per minute, tracked via a sliding window in Redis.

### 3. Svix Webhook Signatures
Used securely receive server-to-server lifecycle events from Clerk.
*   **Header:** `svix-id`, `svix-timestamp`, `svix-signature`
*   **Validation:** HMAC SHA-256 signature checked using the `CLERK_WEBHOOK_SECRET`.

## 1. Public Endpoints
No authentication is required.

### 1.1 Health Check
**GET** `/`
Checks if the API gateway and database connection pool are active.

*   **Auth Required:** None
*   **Response:** `200 OK`
```text
"Open Source Radar API is running and database is connected!"
```

### 1.2 Get Trending Repositories
**GET** `/api/trending`
Returns repositories ranked dynamically based on the weighted momentum algorithm.

*   **Auth Required:** None
*   **Query Parameters:**
    *   `limit` (integer, optional, default: 25, max: 100)
    *   `timeframeDays` (integer, optional, valid: 7, 30, 90)
    *   `language` (string, optional)
    *   `category` (string, optional)
    *   `maxStars` (integer, optional)
    *   `vw` (float, optional) - Velocity Weight
    *   `gw` (float, optional) - Growth Weight
    *   `cw` (float, optional) - Contributor Weight
    *   `hw` (float, optional) - Hiring Weight
    *   `sw` (float, optional) - Social Weight
*   **Response:** `200 OK`
```json

  {
    "id": "uuid",
    "githubId": 123456,
    "owner": "techmedaddy",
    "name": "trackopensource",
    "description": "...",

    "categories": ["Backend", "Rust"],
    "stars": 1500,
    "forks": 120,
    "timeframeDays": 30,
    "starsGained": 500,
    "starVelocity": 16.6,
    "growthRatio": 0.5,
    "contributorsGained": 5,
    "contributorGrowth": 0.1,
    "velocityScore": 85.5,
    "growthScore": 70.2,
    "contributorScore": 40.0,
    "activityScore": 60.5,

    "socialScore": 45.0,

    "updatedAt": "2026-06-12T00:00:00Z"
  }
]
```

### 1.3 Get Fastest Growing Repositories
**GET** `/api/fastest-growing`
Returns repositories ranked strictly by `star_velocity` and `stars_gained` rather than the holistic trend formula.

*   **Auth Required:** None
*   **Query Parameters:** Same as `/api/trending`
*   **Response:** `200 OK`
Returns the same `RankedRepository` array schema as `/api/trending`.

### 1.4 Search Repositories
**GET** `/api/search`
Performs ILIKE pattern matching across repository owner, name, description, language, and categories.

*   **Auth Required:** None
*   **Query Parameters:**
    *   `q` (string, required) - Search term
    *   `limit` (integer, optional)
    *   `timeframeDays` (integer, optional)
*   **Response:** `200 OK`
Returns the same `RankedRepository` array schema.

### 1.5 Get Repository Details
**GET** `/api/repos/:id`
Retrieves the deep analytical profile for a single repository.

*   **Auth Required:** None
*   **Path Params:** `id` (UUID)

### 1.6 Get Analytical Facets
**GET** `/api/facets`
Retrieves distinct categories and languages available in the database to populate frontend filter dropdowns.

*   **Auth Required:** None
*   **Response:** `200 OK`
```json
{
  "categories": ["AI", "Backend", "Frontend", ...],
  "languages": ["Rust", "TypeScript", "Python", ...]
}
```

## 2. Webhook Endpoints

### 2.1 Clerk Lifecycle Webhook
**POST** `/api/webhooks/clerk`
Listens for `user.created` events from Clerk to synchronize the local `users` table.

*   **Auth Required:** Svix Signature Headers
*   **Body:** Clerk Webhook Event Schema
*   **Response:** `200 OK` or `400 Bad Request`

---

## 3. Protected Endpoints
These endpoints are used by the Next.js frontend and require an active user session.

*   **Header:** `Authorization: Bearer <clerk_jwt>`

### 3.1 Track New Repository
**POST** `/api/track`
Submits a new repository to the ingestion pipeline.

*   **Body:**
```json
{
  "githubId": 123456,
  "owner": "techmedaddy",
  "name": "trackopensource",
  "description": "A cool radar",
  "language": "Rust",
  "stars": 100,
  "forks": 10
}
```
*   **Response:** `200 OK`
```json
{
  "status": "success",
  "message": "Repository is now being tracked"
}
```

### 3.2 Trigger Manual Scan
**POST** `/api/trigger`
Queues a background job to run the data collector pipeline immediately.
*Note: Rate limited to 3 executions per user per hour (unless `E2E_TEST_MODE=true`).*

*   **Response:** `200 OK`
```json
{
  "status": "success",
  "message": "Scan queued successfully. Worker is processing in background.",
  "job_id": "uuid"
}
```
*   **Error Response:** `429 Too Many Requests`

### 3.3 Get Watchlist
**GET** `/api/watchlists`
Retrieves the list of repository UUIDs the authenticated user is watching.

*   **Response:** `200 OK`
```json
[
  "uuid-1",
  "uuid-2"
]
```

### 3.4 Modify Watchlist
**POST** `/api/watchlists/:id` — Adds a repository to the watchlist.
**DELETE** `/api/watchlists/:id` — Removes a repository from the watchlist.

*   **Response:** `200 OK`

### 3.5 API Key Management
**GET** `/api/keys` — Lists all keys owned by the user (returns prefixes and metadata, never the full key).
**POST** `/api/keys` — Creates a new API key.
**DELETE** `/api/keys/:id` — Revokes an API key.

*   **Create API Key Body:**
```json
{ "name": "Production Key" }
```
*   **Create API Key Response:** `200 OK`
```json
{
  "key": "osr_abcdef1234567890...",
  "apiKey": {
    "id": "uuid",
    "name": "Production Key",
    "prefix": "osr_abcd",
    "createdAt": "2026-06-12T00:00:00Z",
    "lastUsedAt": null
  }
}
```

## 4. V1 Programmatic Endpoints
These endpoints are designed for third-party developers, recruiters, or scripts. They mirror the public endpoints but are heavily rate-limited and require an API key.

*   **Header:** `x-api-key: osr_<key>`
*   **Rate Limit:** 100 requests per minute

### 4.1 V1 Trending
**GET** `/api/v1/trending`
Identical to `/api/trending` but authorized via API key.

### 4.2 V1 Fastest Growing
**GET** `/api/v1/fastest-growing`
Identical to `/api/fastest-growing` but authorized via API key.

### 4.3 V1 Repository Detail
**GET** `/api/v1/repos/:id`
Identical to `/api/repos/:id` but authorized via API key.

## Error Handling

All endpoints follow a unified error response schema handled by the Axum `IntoResponse` implementation (`backend/src/error.rs`).

```json
{
  "error": "Error description here"
}
```

**Common HTTP Status Codes:**
*   `400 Bad Request`: Invalid parameters or body.
*   `401 Unauthorized`: Missing or invalid Clerk JWT or API key.
*   `404 Not Found`: Repository or resource does not exist.
*   `429 Too Many Requests`: Exceeded API key rate limit (100 req/min) or manual trigger limit (3/hour).
*   `500 Internal Server Error`: Database or downstream API failure (internal details are never leaked to the client).
