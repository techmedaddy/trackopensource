# Engineering Highlights

This document serves as an overview of the major architectural decisions, scaling strategies, and technical milestones achieved during the development of TrackOpenSource.

## Cost-Efficient Infrastructure

TrackOpenSource runs a full-stack architecture consisting of a Next.js frontend, Rust API gateway, Rust data collection workers, PostgreSQL, and Redis on a single AWS EC2 t3.small instance.

To avoid premature infrastructure scaling, a Linux swap strategy was implemented to extend available memory during build and data-processing workloads. This enabled stable operation of the entire platform while maintaining low hosting costs.

## Ranking & Discovery Engine

Built a multi-factor repository ranking system that combines:

*   GitHub growth velocity
*   Historical star movement
*   Social discussion signals
*   Hiring demand extracted from job postings

The ranking engine generates 7-day, 30-day, and 90-day repository profiles and powers the platform's Hype vs. Hiring discovery matrix.

## Historical Analytics Pipeline

Designed a snapshot-based analytics system that stores repository metrics over time and computes growth rates, momentum scores, and trend acceleration from historical baselines rather than point-in-time GitHub statistics.

This enables longitudinal analysis of open-source projects instead of relying solely on current repository popularity.

## Production Data Operations

Implemented reproducible database backup and restoration workflows using PostgreSQL dump and restore tooling, allowing production datasets to be mirrored locally for debugging, testing, and UI verification.

## Platform Reliability

Improved resilience of external data collection services through timeout enforcement, fault isolation, and graceful degradation when third-party APIs become unavailable.

Additional frontend improvements included asset proxying, cache optimization, and dashboard rendering enhancements to ensure consistent behavior across browsers and network conditions.
